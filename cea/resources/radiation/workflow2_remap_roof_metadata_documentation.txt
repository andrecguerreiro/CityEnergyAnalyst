REMAPPING CUSTOM ROOF METADATA ONTO EXISTING CEA RADIATION SENSORS
===================================================================

Purpose
-------
This routine modifies only the metadata consumed by `photovoltaic.py`, not the radiation simulation outputs themselves.

More specifically, it remaps:
- roof area per sensor (`AREA_m2`)
- roof normal per sensor (`Xdir`, `Ydir`, `Zdir`)
- roof orientation label (`orientation`)

inside each building's `Bxxx_geometry.csv`, while keeping:
- the same SURFACE ids
- the same number of rows / sensors
- the same radiation time series coming from Daysim / Radiance

This allows an experiment where:
1. radiation is still the one computed on the original CEA roof sensor set,
2. but PV placement and PV yield calculations in `photovoltaic.py` see updated roof area and updated roof normals derived from custom roof polygons.

In short:
- irradiance / insolation stays fixed,
- geometry metadata seen by PV is changed.

High-level idea
---------------
CEA radiation gives you a fixed set of roof sensors for a building.
Your custom workflow gives you a different roof description: a set of custom roof faces, each with:
- a 3D area,
- a unit normal,
- an XY footprint.

The problem is therefore:

"How do we transfer the custom roof geometry information to the existing sensor set without changing the sensor count or sensor identities?"

The chosen solution is not to create new sensors, but to redistribute the custom roof information across the existing sensors using distance-based affinities.

This creates, for each original roof sensor:
- an effective roof area,
- an effective normal,
that collectively represent the custom roof.

Mathematical formulation
========================

1) Original sensor set
----------------------
For one building, let the original roof sensor set be:

S = {1, ..., n}

Each sensor j belongs to the original CEA radiation metadata and has an XY position:

x_j = (x_j, y_j)

These positions come from the existing `Bxxx_geometry.csv` rows where `TYPE == 'roofs'`.

The radiation time series associated with original sensor j is:

I_j(t),   t = 1, ..., T

This routine does NOT change I_j(t).

2) Custom roof faces
--------------------
Let the custom roof decomposition be:

F = {1, ..., m}

Each custom face i has:
- 3D area A_i
- unit normal n_i in R^3, with ||n_i|| = 1 and n_{i,z} >= 0
- XY footprint polygon P_i

The upward convention matters because CEA expects roof normals to point upward.

3) Affinity between a custom face and a sensor
----------------------------------------------
For each face i and each sensor j, define an affinity:

alpha_{ij} = 1 / ( d(x_j, P_i) + epsilon )

where:
- d(x_j, P_i) is the planar distance between sensor j and the XY footprint of face i,
- epsilon is a small numerical stabilizer (here 1e-6).

Interpretation:
- if the sensor lies inside the face footprint, distance is 0 and affinity is very large,
- nearby sensors get higher affinity,
- far sensors get lower affinity.

This is exactly the idea from your notes: the influence of each custom face is shared across sensors according to closeness in XY.

4) Row normalization: distributing each face across sensors
-----------------------------------------------------------
Construct the affinity matrix A with rows = faces and columns = sensors:

A = [alpha_{ij}]  in R^{m x n}

Then normalize each row:

p_{ij} = alpha_{ij} / sum_{k=1}^n alpha_{ik}

For each face i:

sum_{j=1}^n p_{ij} = 1

Interpretation:
- each custom face distributes 100% of its area and directional influence over the existing sensors,
- closer sensors receive a larger share.

This matches your note:
"each face distributes 100% of its influence among sensors".

5) Area redistribution
----------------------
The effective roof area assigned to original sensor j is:

A~_j = sum_{i=1}^m p_{ij} A_i

Interpretation:
- each sensor collects area contributions from all custom faces,
- the total roof area is exactly conserved.

Indeed:

sum_{j=1}^n A~_j
= sum_{j=1}^n sum_{i=1}^m p_{ij} A_i
= sum_{i=1}^m A_i sum_{j=1}^n p_{ij}
= sum_{i=1}^m A_i

So the remapped total roof area equals the total 3D area of the custom roof faces.

This is one of the main properties of the method.

6) Normal redistribution
------------------------
To obtain one effective normal for each original sensor j, first build the weighted sum vector:

v_j = sum_{i=1}^m p_{ij} A_i n_i

Then normalize it:

n~_j = v_j / ||v_j||

Interpretation:
- area matters: larger faces should influence the effective normal more strongly,
- the sensor's final normal becomes an area-weighted blend of nearby custom face normals.

This is exactly the workflow written in your notes:
1. build weighted sum vector,
2. normalize to a unit vector.

What is preserved and what is changed
=====================================

Preserved
---------
1. The original roof sensor count n.
2. The original SURFACE identifiers and row structure in `Bxxx_geometry.csv`.
3. The original radiation time series per sensor.
4. The non-roof rows in the metadata file.

Changed
-------
1. `AREA_m2` for roof sensors.
2. `Xdir`, `Ydir`, `Zdir` for roof sensors.
3. `orientation` for roof sensors (set to `top`).

Physical meaning
================

What this method means physically
---------------------------------
This routine does not claim that the original radiation sensors now literally lie on the custom roof faces.
Instead, it says:

"Use the already-simulated radiation values as sampling locations, but reinterpret the amount of roof area and local roof orientation associated with each sampling location."

So each original sensor becomes an effective carrier of:
- some redistributed share of custom roof area,
- some redistributed share of custom roof orientation.

This is a metadata remapping method, not a new geometric radiation simulation.

What this is useful for
-----------------------
This is useful when you want to explore the effect of a more realistic roof decomposition in the PV stage only, without rerunning the full radiation pipeline.

In particular, it is useful if your interest is mainly in:
- panel tilt / azimuth assignment,
- available roof area,
- PV capacity estimation,
- comparing flat-roof metadata vs custom-roof metadata under the same radiation field.

What this does NOT capture exactly
----------------------------------
Because the radiation simulation is unchanged, the following are not fully re-simulated under the custom geometry:
- self-shading between custom roof planes,
- shadow changes caused by the altered roof shape,
- changes in sky view / obstruction caused by new roof slopes,
- exact local irradiance changes that would arise if sensors were actually moved onto the custom faces.

So the method is best interpreted as:
- exact in area conservation,
- approximate in directional remapping,
- approximate in radiation-shading consistency.

How this connects to photovoltaic.py
====================================

Why `Bxxx_geometry.csv` matters
-------------------------------
In the CEA workflow, `photovoltaic.py` uses radiation outputs plus sensor metadata.
The metadata file contains, among other things:
- sensor area,
- surface normal direction,
- surface type.

This routine changes only that metadata input.
That means `photovoltaic.py` will still read the same radiation results, but it will interpret them through modified roof geometry descriptors.

Conceptually:
- radiation intensity per sensor stays the same,
- panel grouping / orientation logic sees a new effective roof geometry.

Code walkthrough
================

1) Data structure for custom roof faces
---------------------------------------
Code:
- `@dataclass class RoofFace`

Purpose:
Store the information needed for remapping:
- `building`
- `roof_id`
- `polygon_xy`
- `normal`
- `area_3d`

This is the mathematical face i in the formulation above.

2) Unit-vector normalization
----------------------------
Code:
- `unit(v)`

Mathematical role:

unit(v) = v / ||v||

Used when:
- constructing face normals,
- constructing final sensor normals.

3) Computing custom face normals
--------------------------------
Code:
- `polygon_normal(coords_xyz)`

What it does:
- takes the first three points of a polygon,
- computes a cross product,
- normalizes the result,
- flips it if the z-component is negative.

Mathematical role:
This builds n_i for each custom face.

Important detail:
The code enforces upward-pointing normals:
- if `n[2] < 0`, then `n = -n`

This matches your note that the normal should point upward and keeps compatibility with CEA roof assumptions.

4) Computing 3D polygon area
----------------------------
Code:
- `polygon_area_3d(coords_xyz)`

What it does:
- triangulates the planar polygon by a fan from the first vertex,
- sums triangle areas using cross products.

Mathematical role:
This computes A_i, the true 3D face area.

This is important because the remapping should preserve actual sloped roof area, not the 2D plan area.

5) Loading custom roof faces from the GeoJSON
---------------------------------------------
Code:
- `load_custom_roof_faces(roof_file, target_crs)`

What it does:
- reads the custom roof file,
- checks that a `building` column exists,
- reprojects to the target CRS if needed,
- iterates over Polygon / MultiPolygon geometries,
- extracts for each valid polygon:
  - 3D coordinates,
  - face normal,
  - 3D area,
  - XY footprint polygon,
- stores faces grouped by building.

Mathematical role:
This creates the set F = {1, ..., m} for each building.

Important assumptions:
- the roof file stores geometries with XYZ coordinates,
- the XY coordinates are meaningful in the scenario projected CRS,
- polygons are planar enough for a single face normal to make sense.

6) Defining affinity
--------------------
Code:
- `affinity(face, point_xy)`

Definition in code:

return 1.0 / (d + 1e-6)

where `d = face.polygon_xy.distance(point_xy)`.

Mathematical role:
This is alpha_{ij}.

Interpretation:
- sensor inside footprint -> d = 0 -> very large weight,
- sensor near footprint -> large weight,
- sensor far from footprint -> small weight.

This directly implements the affinity idea in your notes.

7) Main remapping routine
-------------------------
Code:
- `remap_building_metadata(df, faces)`

This is the core of the method.

Step 7.1: isolate roof rows
~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `roof_mask = df["TYPE"] == "roofs"`
- `roof_df = df.loc[roof_mask].copy()`

Meaning:
Only roof sensors are remapped. Walls and windows are left unchanged.

Step 7.2: collect original sensor XY positions
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `sensor_xy = roof_df[["Xcoor", "Ycoor"]].to_numpy(dtype=float)`

Meaning:
These are the x_j positions in the formulation.

Step 7.3: build affinity matrix
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `A = np.zeros((n_faces, n_sensors), dtype=float)`
- nested loop over faces i and sensors j
- `A[i, j] = affinity(face, p)`

Meaning:
This constructs A = [alpha_{ij}].

Step 7.4: row-normalize affinities
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `row_sums = A.sum(axis=1, keepdims=True)`
- `P = A / row_sums`

Meaning:
This constructs P = [p_{ij}] with each row summing to 1.

Step 7.5: collect face areas and normals
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `face_areas = np.array([f.area_3d for f in faces], dtype=float)`
- `normals = np.array([f.normal for f in faces], dtype=float)`

Step 7.6: redistribute area exactly
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `area_per_sensor = (P.T @ face_areas)`

Dimensions:
- P.T has shape [sensor, face]
- face_areas has shape [face]
- result has shape [sensor]

Mathematical identity:

A~_j = sum_i p_{ij} A_i

This is the exact area-conservation step.

Step 7.7: redistribute normals
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- `weighted = (P.T * face_areas) @ normals`
- `normals_per_sensor = np.array([unit(v) for v in weighted], dtype=float)`

Mathematical identity:

v_j = sum_i p_{ij} A_i n_i
n~_j = unit(v_j)

Step 7.8: write remapped metadata back
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Code:
- overwrite `AREA_m2`
- overwrite `Xdir`, `Ydir`, `Zdir`
- set `orientation = "top"`


8) Output handling
------------------
Code:
- `output_path(metadata_path, suffix)`
- `--in-place` option with `.bak` backup


9) Main execution flow
----------------------
Code:
- `main()`

Execution sequence:
1. Parse arguments.
2. Create `InputLocator` from scenario.
3. Read zone geometry to recover target CRS.
4. Load custom roof file.
5. Group roof faces by building.
6. For each building:
   - locate `Bxxx_geometry.csv` via `locator.get_radiation_metadata(building)`
   - read the metadata CSV,
   - compute roof area before remap,
   - apply `remap_building_metadata`,
   - compute roof area after remap,
   - compare with custom roof total,
   - write output.

The printed summary is a useful sanity check:
- roof area before
- roof area after
- custom roof total

Under correct operation, `after` should match `custom_total` up to numerical precision.
