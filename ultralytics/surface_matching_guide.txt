Guide: Surface Matching And Generation In fixedbox_html.py
Source file: fixedbox_html.py
Scope: only how buildings are matched and how roof surfaces are generated

========================================================================
1) What the relevant pipeline does
========================================================================

The relevant path in fixedbox_html.py is:

1. Build predicted building objects from model output.
2. Compute IoU between each OSM building and each predicted building.
3. For each OSM building, pick the best prediction and keep it only if IoU > 0.3.
4. For accepted matches, call topology_converter_mine(pred.raw_roof_data, osm_feat).
5. topology_converter_mine generates roof surface meshes (PyVista) per face.
6. Generated meshes are stored in face_data["intersections"] and rendered in render_3d_tiles().

========================================================================
3) Matching OSM buildings to predictions
========================================================================

3.1 IoU calculation

Code excerpt:

def compute_area_overlap(osm_building, prediction_building) -> float:
    tr = Transformer.from_crs("EPSG:4326", "EPSG:3763", always_xy=True)

    xs, ys = zip(*[tr.transform(lon, lat)
                   for lon, lat in osm_building["geometry"]["coordinates"][0]])
    osm_box = [min(xs), min(ys), max(xs), max(ys)]
    pred_box = prediction_building.box_coords_in_epsg_3763

    ix0, iy0 = max(osm_box[0], pred_box[0]), max(osm_box[1], pred_box[1])
    ix1, iy1 = min(osm_box[2], pred_box[2]), min(osm_box[3], pred_box[3])
    inter_area = max(0.0, ix1 - ix0) * max(0.0, iy1 - iy0)

    area_osm  = (osm_box[2]  - osm_box[0])  * (osm_box[3]  - osm_box[1])
    area_pred = (pred_box[2] - pred_box[0]) * (pred_box[3] - pred_box[1])
    union_area = area_osm + area_pred - inter_area
    return inter_area / union_area if union_area > 0 else 0.0

Important:
- OSM polygon is transformed from EPSG:4326 to EPSG:3763.
- IoU is bbox-vs-bbox in EPSG:3763.
- It is not polygon-vs-polygon IoU.

========================================================================
6) How each roof tile surface is geometrically created
========================================================================

6.1 Plane normal computation

Code excerpt:

def planenormal(face_id, inc, ori, axis_aligned_bounding_box_rotation):
    tilt = inc * (math.pi / 2)
    global_azimuth = (ori - 0.5) * (math.pi / 2) + base_ori_rad
    azimuth = global_azimuth + axis_aligned_bounding_box_rotation
    nz = math.cos(tilt)
    nx = math.sin(tilt) * math.cos(azimuth)
    ny = math.sin(tilt) * math.sin(azimuth)
    return [nx, ny, nz]

Meaning:
- `inc` controls slope (0..1 mapped to 0..90 deg).
- `ori` controls orientation around the face baseline.
- Building rotation angle is injected into azimuth.

6.2 Tile generation by extrusion + slice

Code excerpt:

def rooftile(corners, plane_point, plane_normal, height=1000.0):
    pts = np.array(corners)
    if pts.shape[1] == 2:
        pts = np.column_stack([pts, np.zeros(len(pts))])

    footprint = pv.PolyData(pts, faces=faces)
    cuboid = footprint.extrude((0, 0, height), capping=True)
    intersection_polygon = cuboid.slice(normal=plane_normal, origin=plane_point)
    return intersection_polygon

Meaning:
- Start with a local 2D polygon patch.
- Extrude vertically to a volume.
- Slice with the face plane.
- The slice result is the roof surface mesh for that patch.

7) How multi-face rooftops are partitioned
========================================================================

For multi-face codes, the converter:
- defines split lines (depends on `code`),
- splits the local rectangle with Shapely,
- assigns each split part to a face by centroid,
- builds that part's tile with the corresponding face normal.

So the visualized surfaces are exactly those generated in topology_converter_mine.


========================================================================
10) Important conceptual clarification
========================================================================

Question: "Is it creating equivalent geometries based on the surface area in each direction?"

In this code, no explicit area-balancing optimization is performed.

What it does:
- Uses directional probabilities to decide active faces.
- Uses predefined split templates per topology code.
- Assigns parts by centroid rules.
- Generates surfaces from those parts and face normals.

What it does not do:
- Solve for equal-area faces.
- Fit areas to directional target ratios.
- Run a global geometric optimization over roof surface area.

11) Quick debugging focus (matching + surfaces only)
========================================================================

1. If no surfaces render, check whether many OSM buildings fail IoU > 0.3.
2. If matches exist but some buildings still have no surfaces, inspect:
   - computed `code` in topology_converter_mine,
   - whether the corresponding case is producing `intersections`.
3. If intersections exist but view is empty, inspect tile validity before `delaunay_2d()`.
